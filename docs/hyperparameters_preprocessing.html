สรุป Preprocessing และ Hyperparameters

AI Classification of Cyber Attacks — CICIDS2017 (2,497,980 แถว, 9 คลาส, temporal split 70/30)
อ้างอิงจากโค้ด train.py และผลรัน results/cicids2017_temporal_v1/ · จัดทำ 28 ก.ย. 2026

1. Preprocessing

1.1 การทำความสะอาดข้อมูล (ทำทีละไฟล์ CSV)

ที่มา: train.py ฟังก์ชัน _clean_one_frame

  1. ตัดช่องว่างหน้า/หลังชื่อคอลัมน์ (ไฟล์ CICIDS2017 มีช่องว่างนำหน้าชื่อ)
  2. บันทึก _row_index (ตำแหน่งแถวในไฟล์ CSV ดิบ) ก่อนลบแถวใด ๆ เพื่อใช้เป็นตัวเรียงลำดับเวลาของ split
  3. เปลี่ยนชื่อ Fwd Pkts/s → Fwd Packets/s และ Bwd Pkts/s → Bwd Packets/s
  4. ลบคอลัมน์ซ้ำ Fwd Header Length.1
  5. ลบคอลัมน์ที่ทำให้ข้อมูลรั่ว (ถ้ามี): Flow ID, Source/Destination IP, Src/Dst IP, Source Port, Src Port, Timestamp
  6. ลบคอลัมน์ Protocol
  7. ลบแถวที่เป็น header เสีย (ค่า label เท่ากับ "Label")
  8. แปลง label ด้วย normalize_label จาก 15 label ดิบ เหลือ 9 คลาส: BENIGN, DoS, DDoS, PortScan, Bot, Web Attack, Brute Force, Infiltration, Heartbleed — แถวที่แปลงได้ Other จะถูกลบ
  9. บังคับทุก feature เป็นตัวเลข (pd.to_numeric(errors="coerce")) แล้วแปลงเป็น float32
  10. แปลงค่า ±Inf เป็น NaN แล้วลบแถวที่มี NaN

1.2 หลังรวมทุกไฟล์

ที่มา: load_and_clean_cached

  • ตรวจว่ามีครบ 8 capture file — ถ้าขาดจะหยุดทำงาน เพราะแต่ละคลาสอยู่ในไฟล์เดียว ขาดไฟล์คือคลาสหายทั้งคลาส
  • เพิ่ม metadata source_file, dataset_id, capture_window (ไม่ป้อนเข้าโมเดล)
  • ลบแถวที่ซ้ำกันทุกคอลัมน์ข้ามไฟล์ (ไม่นับคอลัมน์ metadata)
  • cache ไว้ที่ data/processed/cicids2017_clean.parquet (2,497,980 แถว)

1.3 การแบ่ง Train / Test

  • ตรวจลำดับเวลาของ _row_index เทียบกับตารางโจมตีที่ CIC เผยแพร่ (validate_capture_chronology)
  • แบ่งตามเวลา 70/30 ภายในแต่ละกลุ่ม (ไฟล์, คลาส) (temporal_source_split) โดยทุกคลาสมีอย่างน้อย 3 แถวใน test (min_test_per_class=3)
  • ตรวจจำนวนแถวต่อคลาสเทียบกับ manifest configs/splits/cicids2017_temporal_70_30.json — ไม่ตรงจะหยุดทำงาน
  • ไม่มีชุด calibration (threshold_validation_size = 0.0)
  • LabelEncoder เข้ารหัส label หลังแบ่งข้อมูลแล้ว

1.4 Pipeline ภายในโมเดล

ทุกโมเดลใช้โครงเดียวกัน และ fit ใหม่ทุก CV fold จึงไม่มีข้อมูลรั่วจาก test/validation

SimpleImputer(strategy="median") → StandardScaler() → [sampler ถ้าเลือก] → classifier

1.5 การจัดการคลาสไม่สมดุล

ค่าเริ่มต้น imbalance_strategy = "class_weight" ใช้กับทุกโมเดลเหมือนกัน:

โมเดลวิธีถ่วงน้ำหนัก
Random Forestclass_weight="balanced_subsample"
LightGBM, Logistic Regression, meta-learner ของ Stackingclass_weight="balanced"
CatBoostauto_class_weights="Balanced"
XGBoost, MLPไม่มีพารามิเตอร์นี้ จึงใช้ wrapper BalancedXGBClassifier / BalancedMLPClassifier ที่คำนวณ compute_sample_weight("balanced") ภายในแต่ละ fold

ทางเลือกอื่น: targeted, random_over, borderline_smote, smoteenn (k_neighbors=5) — รันภายใน pipeline

ข้อสังเกต: subsample_n ใน CONFIG และใน preset ถูกอ่านไปใช้แค่ในโหมด --smoke และในรายงานเท่านั้น ในเส้นทาง temporal ข้อมูลที่ใช้คือทั้ง corpus หลังทำความสะอาด โดยไม่มีการ subsample
