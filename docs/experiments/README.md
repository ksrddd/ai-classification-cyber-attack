# สารบัญการทดลองทั้งหมด

รวมทุกการทดลองของโครงงาน แยกตามชุดข้อมูลและตามรอบที่ทำ เพื่อให้ย้อนดูและเปรียบเทียบได้

```
docs/experiments/
├── ids2017/         การเทรนบน CICIDS2017
├── ids2018/         การเทรนบน CSE-CIC-IDS2018
└── crossdataset/    การถ่ายทอดข้ามชุดข้อมูล แยกเป็น 4 รอบ
```

แต่ละโฟลเดอร์แยกเป็น `report/` งานที่อ่าน `data/` ตัวเลขที่รายงานอ้างอิง และ `code/` สคริปต์
ที่สร้างตัวเลขนั้น

## บทเรียนที่ใช้ได้กับทุกสาย

### 1. รายงาน macro-F1 สองแบบเสมอ

ทุกชุดข้อมูลมีคลาสที่ test flow น้อยเกินกว่าจะวัดผลได้ และคลาสเหล่านั้นถือน้ำหนักเท่ากับคลาส
ที่มีแสนแถว

| ชุด | คลาสที่วัดไม่ได้ | จำนวน test flow |
|---|---|---|
| 2017 | Heartbleed | 4 |
| 2017 | Infiltration | 11 |
| 2018 | SQL Injection | 1 |
| 2018 | Brute Force -XSS | 2 |
| 2018 | Brute Force -Web | 6 |
| 2018 | DDOS attack-LOIC-UDP | 16 |
| cross | Web Attack | 17 ถึง 27 |

ต้องรายงานทั้งค่าที่นับครบทุกคลาส และค่าที่นับเฉพาะคลาสที่มีข้อมูลพอ ควบคู่กันเสมอ

### 2. บางคลาสติดเพดานที่ข้อมูล ไม่ใช่ที่โมเดล

เมื่อ logistic regression กับ gradient boosting ที่ทูนแล้วได้คะแนนเท่ากันในคลาสหนึ่ง เพดานนั้น
ไม่ได้อยู่ที่โมเดล

| ชุด | คลาส | ช่วงคะแนนทุกโมเดล |
|---|---|---|
| 2017 | Bot | recall 0.150 ถึง 0.161 |
| 2018 | DoS SlowHTTPTest | F1 0.619 ถึง 0.638 |
| 2018 | FTP-BruteForce | F1 0.755 ถึง 0.800 |
| 2018 | Infilteration | F1 0.00 ถึง 0.13 |

**ทั้งสองชุดข้อมูลมีคลาสแบบนี้** ข้อสันนิษฐานว่า 2017 สะอาดกว่า 2018 จึงจริงเพียงบางส่วน

### 3. การทูนต้องแฟร์ ไม่ใช่แค่จำนวนครั้งเท่ากัน

การให้ทุกโมเดลลองเท่ากันบน search space ที่ขนาดต่างกันสิบเท่าไม่ใช่การเปรียบเทียบที่ยุติธรรม
เมื่อแก้ให้ทุก space เท่ากันที่ 144 ชุด อันดับเปลี่ยน 10 จาก 14 ตำแหน่ง แต่คะแนนบนคลาสที่วัดได้
ไม่ขยับเกิน 0.007 — อันดับเดิมสะท้อนโชคในการค้น ไม่ใช่คุณภาพของโมเดล

### 4. วิธีแบ่งข้อมูลเปลี่ยนข้อสรุป ไม่ใช่แค่เปลี่ยนตัวเลข

การแบ่งแบบสุ่มทำให้เพดานของ 2017 เฟ้อขึ้น 0.21 ถึง 0.32 ส่วน 2018 เฟ้อขึ้นเพียง 0.006 ถึง
0.033 และเมื่อใช้การแบ่งแบบสุ่ม ความไม่สมมาตรของการถ่ายทอดข้ามชุดข้อมูลจะมองไม่เห็นเลย
