# Cross-Dataset ตาม Protocol เต็มรูปแบบ CICIDS2017 และ CSE-CIC-IDS2018

รันวันที่ 10 สิงหาคม 2569 ผลลัพธ์ 280 แถว จาก 4 combination × 2 split mode × 5 seeds × 7 โมเดล

## 1. สรุปสั้น

ผลสำคัญที่สุดสามข้อ

**1. การถ่ายทอดข้ามชุดข้อมูลไม่สมมาตรอย่างรุนแรง** เทรนด้วย 2018 แล้วทดสอบกับ 2017 กู้คืน
ประสิทธิภาพได้ถึง 73.9% ของช่วงที่เป็นไปได้ ส่วนทิศกลับกันได้เพียง 7.5%

**2. วิธีแบ่งข้อมูลไม่ได้เปลี่ยนแค่ตัวเลข แต่เปลี่ยนข้อสรุป** ภายใต้การแบ่งแบบสุ่มซึ่งเป็นวิธี
ที่ protocol กำหนด ทั้งสองทิศดูใกล้เคียงกัน (31.1% กับ 25.8%) ความไม่สมมาตรที่เป็นข้อค้นพบ
หลักจะมองไม่เห็นเลย

**3. เมื่อตัดสองคลาสที่พังเชิงโครงสร้างออก การถ่ายทอดทำงานได้จริง** stacking ที่เทรนด้วย 2018
ได้ macro-F1 0.806 บนห้าคลาสที่เหลือเมื่อทดสอบกับ 2017

## 2. Protocol ที่ใช้

| ข้อกำหนด | ค่าที่ใช้ |
|---|---|
| Features | 77 shared |
| Classes | 7 shared เทรนด้วย 7 คลาสตั้งแต่ต้น |
| ขนาดตัวอย่าง | 300,000 แถวต่อ dataset รักษา rare class |
| การแบ่ง | train 60 / calibration 10 / test 30 |
| Seeds | 5 (42 ถึง 46) |
| Split mode | สุ่ม และ ตามลำดับเวลา |
| Tuning | ไม่ทูน ใช้ค่า default เหมือนกันทั้งสองฝั่ง |

ไม่ทูนโดยตั้งใจ ช่องว่างที่กำลังวัดอยู่ระดับ 0.4 ถึง 0.6 ส่วนการทูนขยับโมเดลเหล่านี้ได้
0.01 ถึง 0.05 การนำ hyperparameter ที่ทูนไว้กับ 2018 มาใช้จะให้ความได้เปรียบกับฝั่งหนึ่ง
ซึ่งจะปรากฏออกมาเหมือนเป็นผลของ dataset

preprocessor fit ด้วยชุดที่ใช้เทรนเท่านั้น แล้วนำไปใช้กับ test ทั้งสองฝั่งโดยไม่ปรับอะไร
นั่นคือความหมายของการถ่ายทอด

### 3.1 กฎ clean ใช้ชุดเดียวกันทั้งสองฝั่ง

แปลงค่าอนันต์เป็นค่าว่าง ทิ้งแถวที่มีค่าไม่สมบูรณ์ ทิ้งแถวซ้ำโดยเทียบเฉพาะ feature กับ label

**การ clean 2017 เป็น no-op สมบูรณ์ ไม่มีแถวใดถูกตัดเลย** ซึ่งยืนยันว่ากฎที่ใช้ตรงกับกฎที่
สร้างไฟล์ 2017 ขึ้นมาจริง ไม่ใช่แค่ใกล้เคียง

**ฝั่ง 2018 ถูกตัดไป 12.4%** แยกเป็นค่าไม่สมบูรณ์ 1,738 แถว และแถวซ้ำ 35,561 แถว จำนวนแถว
ซ้ำสูงกว่าที่ประเมินไว้ตอนแรกมาก เพราะเมื่อไม่นับคอลัมน์ IP, port และ timestamp แล้ว flow
จำนวนมากมีค่าเหมือนกันทุกประการ

### 3.2 จำนวนต่อคลาสไม่เท่ากัน และเป็นข้อมูลสำคัญในการอ่านผล

| คลาส | 2017 | 2018 | ต่างกัน |
|---|---|---|---|
| Web Attack | 2,143 | 17 | 126 เท่า |
| Infiltration | 36 | 2,946 | 82 เท่า |
| Brute Force | 9,150 | 1,798 | 5.1 เท่า |

ชุดคลาสเหมือนกันแล้ว แต่จำนวนไม่เท่ากัน ความต่างของสัดส่วนคือ prior shift ซึ่งเป็นองค์ประกอบ
หนึ่งของ domain shift ที่กำลังวัดอยู่ จึงไม่ควรบังคับให้เท่ากัน แต่ต้องรายงานไว้

**สองคลาสที่ต่างกันเกิน 80 เท่า คือสองคลาสที่ได้ F1 เท่ากับศูนย์ในทุกทิศทุกโมเดล**

เปอร์เซ็นต์ที่กู้คืนได้ วัดจากช่วงระหว่างการเดาว่าทุกแถวเป็น Benign กับเพดานของชุดนั้น

## 6. ผลที่สาม ห้าในเจ็ดคลาสถ่ายทอดได้จริง

macro-F1 เฉพาะห้าคลาสที่ไม่ได้พังเชิงโครงสร้าง วัดตอนข้ามชุดข้อมูลแบบแบ่งตามลำดับเวลา

| เทรนด้วย | โมเดล | Benign | DDoS | DoS | Brute Force | Bot | รวม 5 คลาส |
|---|---|---|---|---|---|---|---|
| 2018 | stacking | 0.951 | 0.620 | 0.640 | 0.883 | 0.936 | **0.806** |
| 2018 | lightgbm | 0.942 | 0.032 | 0.698 | 0.889 | 0.943 | 0.701 |
| 2018 | xgboost | 0.878 | 0.029 | 0.486 | 0.902 | 0.765 | 0.612 |
| 2018 | mlp | 0.933 | 0.001 | 0.274 | 0.914 | 0.000 | 0.424 |
| 2018 | catboost | 0.926 | 0.333 | 0.674 | 0.005 | 0.000 | 0.388 |
| 2018 | logistic_regression | 0.936 | 0.053 | 0.208 | 0.737 | 0.000 | 0.387 |
| 2017 | lightgbm | 0.926 | 0.000 | 0.153 | 0.000 | 0.181 | 0.252 |
| 2017 | ที่เหลือทุกตัว | ~0.925 | 0.000 | ~0.14 | 0.000 | 0.000 | ~0.21 |

**0.806 คือระดับที่ใช้งานได้จริง** ไม่ใช่ 0.24 ที่เห็นเมื่อเฉลี่ยรวมทั้งเจ็ดคลาส

Brute Force ทำได้ถึง 0.914 และ Bot ทำได้ 0.943 ซึ่งเป็นการยืนยันว่าความรู้เรื่องการโจมตี
บางประเภทถ่ายทอดข้ามชุดข้อมูลได้จริง ไม่ใช่แค่ความรู้เรื่อง traffic ปกติอย่างที่การทดลอง
ก่อนหน้านี้ชี้ไว้

**เปรียบเทียบกับการทดลองก่อนหน้า** เมื่อใช้โมเดลที่เทรนด้วย 9 คลาสแล้วยุบผลเป็น 7 ทีหลัง
Brute Force ได้เพียง 0.27 พอเทรนด้วย 7 คลาสตั้งแต่ต้นได้ 0.88 ถึง 0.91 การทำให้ชุดคลาส
ตรงกันจึงมีผลมากกว่าที่ประมาณไว้ก่อนหน้านี้มาก

## 7. สองคลาสที่ไม่ถ่ายทอดเลย

`Infiltration` และ `Web Attack` ได้ F1 เท่ากับศูนย์ในทุกทิศ ทุกโมเดล ทุก seed

**Web Attack** เป็นปัญหาเชิงจำนวนล้วน ๆ ฝั่ง 2018 มีเพียง 17 แถวทั้งชุด เหลือราวสิบแถวตอน
เทรนและห้าแถวตอนทดสอบ ไม่ว่าจะเทรนหรือทดสอบก็ไม่มีข้อมูลพอ

**Infiltration** ซับซ้อนกว่านั้น ทิศ 2018 ไป 2017 มีข้อมูลเทรนราว 1,700 แถวซึ่งเพียงพอ แต่ยัง
ได้ศูนย์ และแม้แต่ตอนเทรนกับทดสอบภายในชุดเดียวกัน คลาสนี้ก็ได้เพียง 0.05 ถึง 0.13 ในทุกโมเดล
ตั้งแต่ logistic regression จนถึง catboost จึงเป็นปัญหาคุณภาพของ label ไม่ใช่ปัญหาที่แก้ได้
ด้วยการปรับวิธีการ

การนำสองคลาสนี้ไปเฉลี่ยรวมทำให้ค่า 0.806 กลายเป็น 0.576 โดยไม่ได้ให้ข้อมูลเพิ่ม จึงควรรายงาน
แยกพร้อมเหตุผล ไม่ใช่ตัดทิ้งเงียบ ๆ และไม่ใช่กลบไว้ในค่าเฉลี่ย

## 8. ข้อสังเกตเรื่องโมเดล

stacking เป็นตัวเดียวที่จับ DDoS ได้ตอนข้ามชุดข้อมูล (0.620 ขณะที่โมเดลเดี่ยวได้ 0.03) และ
เป็นตัวที่กู้คืนได้สูงสุด การรวมโมเดลจึงช่วยลดการยึดติดกับลักษณะเฉพาะของชุดข้อมูลได้จริง

random_forest ให้ผลตรงข้าม กู้คืนได้เพียง 6.0% ต่ำที่สุดในทุกโมเดล ทั้งที่ภายในชุดข้อมูล
เดียวกันทำได้ 0.665 ซึ่งไม่ได้แย่ อาการนี้บ่งชี้ว่ามันเรียนรู้ลักษณะที่ผูกกับชุดข้อมูลมากกว่า
ตัวอื่น

## 9. ข้อจำกัด

1. ฝั่ง 2018 ใช้ตัวอย่าง 300,000 แถวที่สุ่มมาก่อนหน้านี้แล้ว ไม่ได้สุ่มใหม่จาก corpus เต็ม ขณะที่ 2017 สุ่มจาก 2.4 ล้านแถว สองฝั่งจึงมาถึง 300,000 แถวด้วยเส้นทางต่างกัน
2. หลัง clean แล้วฝั่ง 2018 เหลือ 262,701 แถว ไม่ครบ 300,000 ตามที่ protocol กำหนด
3. ตัวบอกลำดับเวลาต่างกัน 2017 ใช้ลำดับแถวในไฟล์ ส่วน 2018 ใช้ timestamp จริง ทั้งคู่เป็นลำดับเวลาเหมือนกัน แต่ได้มาคนละวิธี
4. ช่อง calibration 10% ถูกกันไว้แล้วแต่ยังไม่ได้ใช้ ผลในรายงานนี้ไม่ได้ผ่านการ calibrate
5. ไม่มีการทูน hyperparameter
6. ยังไม่ได้ทำ adversarial validation จึงยังไม่ทราบว่ามี feature ใดที่บ่งบอกว่า record มาจาก dataset ไหน

## 10. ขั้นถัดไปที่ข้อมูลชี้ให้เห็น

1. **ทำ adversarial validation** เป็นชิ้นเดียวในแผนเดิมที่ยังไม่ได้ทำ และตอบคำถามว่าช่องว่างที่เหลือมาจาก feature ที่บ่งบอก dataset เท่าไหร่
2. **ตรวจสอบว่าทำไม stacking ถึงจับ DDoS ได้ตัวเดียว** ถ้าเข้าใจกลไกนี้อาจนำไปสู่วิธีที่ทำให้โมเดลอื่นทำได้ด้วย
3. **ตรวจสอบว่าทำไม random_forest ถ่ายทอดแย่ที่สุด** ทั้งที่ภายในชุดข้อมูลทำได้ดี น่าจะเป็นตัวอย่างที่ชัดที่สุดของการเรียนรู้ลักษณะเฉพาะของชุดข้อมูล
4. **พิจารณาการเทรนด้วยสองชุดรวมกัน** ถ้าเป้าหมายเปลี่ยนจากการวัดการถ่ายทอด เป็นการสร้างโมเดลที่ใช้งานได้จริง
