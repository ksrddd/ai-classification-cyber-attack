# ผล SHAP รอบ 2-3 แบบแบ่ง 70/30

ฉบับก่อนใช้ผลที่ train 60% (โปรโตคอลเดิมกัน calibration 10% ไว้แต่ไม่เคยใช้) ฉบับนี้รันรอบ 2-3 ใหม่ทั้งหมดบน split 70/30 ด้วยสคริปต์และเกณฑ์เดิม ไม่แก้ F ไม่แก้เกณฑ์ ตัวเลขทุกตัวในเอกสารนี้อ่านจากไฟล์ผลโดยตรง ผลที่ train 60% เทียบไว้ในหัวข้อสุดท้าย

เอกสารนี้เอาผลรอบ 2 (LightGBM) กับรอบ 3 (RF, XGBoost, CatBoost) มาจัดเป็น 4 ส่วน ใช้ค่า SHAP รายแถวที่เก็บไว้ตอนรันจริง แล้วสุ่มกลุ่ม feature 2,000 ชุดใหม่ด้วย seed เดิม ได้ค่า G และ p ตรงกับผลรอบ 2-3 ที่รันใหม่ทุกค่า (สคริปต์หยุดถ้าไม่ตรง)

สคริปต์: `scripts/shap_evidence_pack.py`

ไฟล์ผล: `results/crossdataset/importance_comparison/shap_evidence/`

## สรุป

ทิศ 2017 -> 2018 (ทิศที่ใช้ตัดสิน) มี 17 กรณีที่จำนวนแถวพอ ไม่ผ่านเลยสักกรณี และไม่มีกรณีไหนได้ p < 0.05 ที่ใกล้สุดคือ catboost DoS p = 0.063 และ xgboost DoS p = 0.065 ซึ่งต้องต่ำกว่า 0.010 (CatBoost, 5 class) หรือ 0.017 (XGBoost, 3 class) ถึงจะผ่าน RF ได้ G ติดลบ 4 จาก 5 class (Brute Force ได้ +0.004 ซึ่งใกล้ศูนย์)

ทิศ 2018 -> 2017 มี 2 กรณีที่ p < 0.05 คือ lightgbm Bot (G = +0.320, p = 0.024), lightgbm Web Attack (G = +0.331, p = 0.030) แต่ไม่ผ่าน Bonferroni (0.05 / 4 = 0.0125) และ random_forest, catboost ในทิศนี้ได้ G ติดลบทุก class

กลุ่ม feature สุ่ม 13 ตัวก็ได้ G กว้างพอสมควร (95th percentile อยู่ราว 0.11 ถึง 0.35) แปลว่าแถวที่ทายพลาดกับแถวที่ทายถูกต่างกันหลาย feature ไม่ได้ต่างแค่ที่กลุ่ม F

ผมจึงสรุปว่าการทายพลาดตอนข้าม dataset ไม่น่าเกิดจากกลุ่ม fingerprint กลุ่มเดียว น่าจะมาจากหลาย feature ที่ความสัมพันธ์กับ class เปลี่ยนไปเมื่อย้าย dataset ผลนี้เข้ากับคำอธิบายนี้ แต่ยังไม่ได้ทดสอบตรงๆ

ข้อสรุปเหมือนฉบับ 60% ที่เปลี่ยนคือจำนวนกรณีที่นับได้ (จาก 13 เป็น 17 ในทิศตัดสิน) เพราะ SSH-Patator ของ 2017 เข้ามาอยู่ใน train ทำให้โมเดลทาย Brute Force ใน 2018 ถูกบางส่วนและมีแถว caught ให้เทียบได้

## 1. รายชื่อ feature ในกลุ่ม dataset-specific (F)

F มี 13 ตัว เลือกจาก 60 feature (77 column รวม column ที่ซ้ำกันแล้วเหลือ 60) โดยใช้โมเดล adversarial คือ LightGBM ที่เทรนให้ทายว่าแถวมาจาก 2017 หรือ 2018 แล้ววัดความสำคัญของ feature 2 วิธี การเลือก F ไม่ได้ใช้ split 60/10/30 หรือ 70/30 ของโปรโตคอล (ใช้การแบ่งสุ่ม 70/30 ภายในของงาน adversarial) F จึงเป็นชุดเดิมทุกตัว

- permutation importance: นับว่าผ่านถ้าค่าเฉลี่ยเป็นบวกและมากกว่า 2 เท่าของ SD ระหว่าง seed ได้ 18 ตัว

F คือ feature ที่ผ่านทั้งสองวิธี ได้ 13 ตัว ใช้ชุดนี้ตัดสินตั้งแต่รอบ 2

## 2. ค่า SHAP ของแต่ละโมเดลและแต่ละรอบ (seed)

ทุกโมเดลตั้งค่าเหมือนกัน ใช้ split แบบ chronological 70/30 และ seed 42-46

- missed คือ attack ใน test ของ dataset ปลายทางที่โมเดลทายเป็น Benign
- caught คือ attack ใน test ของ dataset ต้นทางที่โมเดลทายถูก
- ใช้ไม่เกิน 1,000 แถวต่อ class ต่อกลุ่มต่อ seed
- ดูเฉพาะ SHAP ของ output Benign ที่เป็นบวก
- s คือสัดส่วนของ SHAP บวกที่มาจาก F เฉลี่ยทุกแถว
- gap = s(missed) - s(caught) ของแต่ละ seed และ G คือค่าเฉลี่ย gap ของ 5 seed
- นับเฉพาะ class ที่มี missed อย่างน้อย 100 แถว และ caught อย่างน้อย 30 แถว ทุก seed

ถ้า F เป็นตัวที่ทำให้ทายเป็น Benign จริง gap ควรเป็นบวกทุก seed

## 3. วิธีสร้างกลุ่ม feature สุ่ม 2,000 ชุด

สุ่มจาก 60 feature ชุดเดียวกับที่ใช้เลือก F ชุดละ 13 ตัวเท่ากับ F ในชุดเดียวกันไม่ซ้ำกัน (`rng.choice(60, size=13, replace=False)`) ใช้ `numpy.random.default_rng(2026)` สุ่มไปจนครบ 2,000 ชุด ทุกโมเดลเริ่มจาก seed เดียวกัน จึงได้ 2,000 ชุดเดียวกัน (และเป็นชุดเดียวกับฉบับ 60% เพราะ seed เหมือนกัน)

แต่ละชุดคำนวณ G แบบเดียวกับ F ทุกขั้น คือคิดทั้ง 5 seed แล้วเฉลี่ย ได้เป็น G_null 2,000 ค่า แล้วคิด p ด้านเดียวจาก

    p = (1 + จำนวน G_null ที่ >= G) / (1 + 2000)

ตอนสุ่มไม่ได้เอา F ออก ชุดสุ่มจึงมี feature ของ F ปนอยู่ได้ เฉลี่ย 2.83 ตัวต่อชุด (0 ถึง 7 ตัว) ผมเช็กด้วยว่าแต่ละ feature ถูกสุ่มได้ใกล้เคียงกัน ควรได้ประมาณ 433 ครั้ง ได้จริง 390 ถึง 478 ครั้ง

ไฟล์: `random_sets.csv` (รายชื่อ feature ของทั้ง 2,000 ชุด และจำนวนที่ซ้ำกับ F), `random_set_feature_counts.csv` (แต่ละ feature ถูกสุ่มกี่ครั้ง)

มี 2 กรณีที่ p < 0.05 คือ lightgbm Bot (G = +0.320, p = 0.024), lightgbm Web Attack (G = +0.331, p = 0.030) แต่ยังสูงกว่าเกณฑ์ Bonferroni (0.05 / 4 = 0.0125) ส่วน RF กับ CatBoost อยู่ต่ำกว่าค่ากลางของ null เกือบทั้งหมด ทิศนี้ไม่ได้ใช้ตัดสินตั้งแต่แรก

## สรุปและข้อจำกัด

ทั้ง 4 โมเดลไม่มีหลักฐานว่า F ทำให้ attack ถูกทายเป็น Benign ตอนข้าม dataset ค่า G ของ F อยู่ในช่วงเดียวกับกลุ่มสุ่ม และแต่ละโมเดลได้เครื่องหมายไม่ตรงกัน กลุ่มสุ่มเองก็ได้ G กว้าง แสดงว่า SHAP ที่ดันไปทาง Benign ในแถวที่ทายพลาดกระจายอยู่หลาย feature

ข้อจำกัดคืองานนี้ทดสอบแค่ F กลุ่มเดียว จึงตัดคำอธิบายว่าเกิดจาก fingerprint กลุ่มเดียวออกได้ แต่ยังไม่ได้ทดสอบโดยตรงว่าความสัมพันธ์ระหว่าง feature กับ decision boundary เปลี่ยนไป และใช้แค่ tree model ไม่มี MLP กับ LR

ผลรอบ 1-3 เก็บไว้ตามที่ได้ ไม่ได้แก้ F หรือเกณฑ์
