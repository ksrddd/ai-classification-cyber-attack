# SHAP เทียบใน dataset ปลายทางเดียวกัน แบบแบ่ง 70/30

เอกสารนี้เทียบ SHAP ใน dataset ปลายทางเดียวกันและ attack class เดียวกัน ระหว่างแถวที่โมเดลทายผิดเป็น Benign กับแถวที่โมเดลทายถูก เพื่อดูว่าความต่างที่เห็นในรอบก่อนมาจากการทายผิดจริง หรือแค่เพราะข้อมูลมาจากคนละ dataset

ฉบับก่อนใช้ผลที่ train 60% ฉบับนี้รันใหม่ทั้งหมดบน split 70/30 ด้วยสคริปต์และเกณฑ์เดิม ตัวเลขทุกตัวอ่านจากไฟล์ผลโดยตรง

สคริปต์: `scripts/shap_within_target.py`

กติกาเขียนไว้ก่อนรัน: `results/crossdataset/importance_comparison/SHAP_WITHIN_TARGET_PREREGISTRATION.md`

ไฟล์ผล: `results/crossdataset/importance_comparison/shap_within_target/`

## สรุป

ไม่ผ่านทุกโมเดล (LightGBM, XGBoost, CatBoost, RF) และทุกชุด feature

class ที่จำนวนแถวพอให้ตัดสินมี 11 กรณี เป็น DoS 8 กรณี (ทุกโมเดลทั้งสองทิศ) ส่วนที่เหลือคือ lightgbm 2017 -> 2018 Brute Force, lightgbm 2018 -> 2017 Bot, xgboost 2018 -> 2017 DDoS ฉบับ 60% มี 9 กรณี ที่เพิ่มขึ้นเพราะ SSH-Patator เข้ามาอยู่ใน train ของ 2017 ทำให้โมเดลทาย Brute Force ใน 2018 ถูกบางส่วน ทิศ 2017 -> 2018 ที่เหลือโมเดลแทบทาย attack ใน 2018 ไม่ถูก ยกเว้น DoS กับ Brute Force

กรณี DoS ทิศ 2017 -> 2018 ตอบคำถามนี้ได้ชัดที่สุด ในรอบ 2-3 gap เป็นบวกใน lightgbm, xgboost, catboost (G_old) แต่พอเทียบกับแถวที่ทายถูกใน 2018 ด้วยกัน G_within ติดลบทั้ง 4 โมเดล และ gap ของแต่ละ seed ติดลบ 20 จาก 20 ค่า แปลว่า gap บวกที่เคยเห็นมาจากการที่ข้อมูลมาจากคนละ dataset ไม่ได้มาจากการทายผิด

G_within ติดลบ 9 จาก 11 กรณี ที่เป็นบวกมี 2 กรณีคือ lightgbm 2017 -> 2018 Brute Force (+0.010, p = 0.249), catboost 2018 -> 2017 DoS (+0.065, p = 0.174) ซึ่ง p สูงกว่า 0.17 ทั้งคู่ p ต่ำสุดของทั้ง 11 กรณีคือ 0.174 (catboost 2018 -> 2017 DoS)

ผลนี้เข้ากับข้อสรุปเดิม คือการทายพลาดตอนข้าม dataset ไม่ได้เกิดจากกลุ่ม fingerprint F กลุ่มเดียว

## 1. วิธีทำ

ใช้โมเดล split และแถวเดียวกับรอบ 2 (LightGBM) และรอบ 3 (RF, XGBoost, CatBoost) ทุกอย่าง แบ่งแถวเป็น 3 กลุ่ม ในแต่ละ class

- missed: แถว attack ใน test ของ dataset ปลายทางที่โมเดลทายเป็น Benign (เอามาจาก cache รอบ 2-3)
- caught_tgt: แถว attack ใน test ของ dataset ปลายทางที่โมเดลทายถูก (กลุ่มใหม่ รอบนี้คำนวณเพิ่มกลุ่มเดียว)
- caught_src: แถว attack ใน test ของ dataset ต้นทางที่โมเดลทายถูก (กลุ่ม caught เดิมของรอบ 2-3)

แถวที่โมเดลทายเป็น attack class อื่นไม่ได้ใช้

ตอนคำนวณ caught_tgt ต้องเทรนโมเดลใหม่ด้วย seed เดิม สคริปต์เช็กว่าจำนวน missed ต่อ class ตรงกับ cache ทุก seed ถ้าไม่ตรงจะหยุด ผลคือตรงทุก seed และค่า G ที่คำนวณใหม่จากกลุ่ม missed กับ caught_src ตรงกับค่า G ของรอบ 2-3 ทั้ง 144 ค่า (ต่างกันมากสุด 0.0000)

ตั้งค่าเหมือนรอบ 2

- 60 feature, split แบบ chronological 70/30, seed 42-46
- ใช้ไม่เกิน 1,000 แถวต่อ class ต่อกลุ่มต่อ seed
- ดูเฉพาะ SHAP ของ output Benign ที่เป็นบวก
- s(กลุ่ม) คือสัดส่วนของ SHAP บวกที่มาจาก F เฉลี่ยทุกแถวในกลุ่ม
- F หลักคือชุด consensus 13 ตัว (ชุดเดียวกับเอกสารผล SHAP รอบ 2-3) และรายงานชุด SHAP 26 ตัวกับ permutation 18 ตัวด้วย

ค่าที่ใช้

- G_within = s(missed) - s(caught_tgt) เฉลี่ย 5 seed ใช้ค่านี้ตัดสิน
- G_old = s(missed) - s(caught_src) คือ G ของรอบ 2-3
- G_dataset = s(caught_tgt) - s(caught_src) ใช้อธิบายอย่างเดียว

G_old = G_within + G_dataset เสมอ เลยแยกได้ว่า gap เดิมมาจากการทายผิดเท่าไหร่ และมาจากการต่าง dataset เท่าไหร่

null คือสุ่มกลุ่ม feature ขนาดเท่ากัน 2,000 ชุด seed 2026 เหมือนรอบ 3

เกณฑ์

- นับเฉพาะกรณีที่มี missed อย่างน้อย 100 แถว และ caught_tgt อย่างน้อย 30 แถว ทุก seed
- ผ่าน: G_within > 0 และ p < 0.05 / (จำนวนกรณีที่นับได้ของโมเดลนั้น)
- ไม่ผ่าน: p >= 0.05 ถ้าอยู่ระหว่างนั้นถือว่าไม่ชัด
- ตัดสินทั้งสองทิศ เพราะทิศ 2017 -> 2018 ทิศเดียวมีกรณีที่นับได้น้อยเกินไป

## 3. ชุด feature อื่น

ผลไม่ผ่านเหมือนกันทั้งชุด SHAP 26 ตัวและชุด permutation 18 ตัว ไม่มีกรณีไหน p < 0.05 (p ต่ำสุด 0.21 และ 0.18)

ชุด permutation ได้เครื่องหมายของ G_within ตรงกับชุดหลัก 11 จาก 11 กรณี

ชุด SHAP 26 ตัวได้เครื่องหมายตรงกับชุดหลัก 6 จาก 11 กรณี กรณีที่ G_within เป็นบวกมี 5 กรณี คือ lightgbm 2017 -> 2018 DoS (+0.030, p = 0.41), lightgbm 2018 -> 2017 DoS (+0.069, p = 0.27), lightgbm 2018 -> 2017 Bot (+0.020, p = 0.40), xgboost 2017 -> 2018 DoS (+0.073, p = 0.21), catboost 2018 -> 2017 DoS (+0.004, p = 0.47) แต่ p ไม่ต่ำกว่า 0.2 คือกลุ่มสุ่มขนาดเท่ากันก็ได้ค่าแบบนี้บ่อย

## 5. ข้อจำกัด

- ตัดสินได้แค่ 11 กรณี และ 8 ใน 11 เป็น DoS ผลนี้จึงพูดได้แน่นอนที่สุดเรื่อง DoS class อื่นมีกรณีเดียวหรือสองกรณีต่อโมเดล
- caught_tgt ของทิศ 2017 -> 2018 เป็นส่วนน้อยของ DoS ใน 2018 (ราว 236-272 แถวต่อ seed เทียบกับ missed กว่า 1,267 แถว) อาจเป็นแถว DoS แบบพิเศษที่คล้าย 2017 มากกว่าปกติ
- ยังเป็นการดู SHAP อย่างเดียว ไม่ได้ทดลองแก้ feature แล้วดูว่าการทายเปลี่ยนไหม

## 6. สิ่งที่ได้จากรอบนี้

คำถามคือ gap ในรอบก่อนมาจากการทายผิด หรือจากการที่ข้อมูลอยู่คนละ dataset

สำหรับ DoS คำตอบคือมาจากการต่าง dataset เมื่อเทียบใน dataset เดียวกัน แถวที่ทายผิดไม่ได้ใช้ F มากกว่าแถวที่ทายถูก

ข้อนี้เพิ่มน้ำหนักให้ข้อสรุปเดิม ว่าการทายพลาดตอนข้าม dataset ไม่ได้มาจากกลุ่ม fingerprint กลุ่มเดียว
