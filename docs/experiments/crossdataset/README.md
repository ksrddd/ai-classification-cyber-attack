# Cross-Dataset CICIDS2017 ↔ CSE-CIC-IDS2018 — สารบัญผลการทดลอง

รวมผลทุกรอบของงาน cross-dataset แยกตามรอบที่ทำ เพื่อให้ย้อนดูและเปรียบเทียบได้

แต่ละรอบแยกเป็นสามส่วนเหมือนกันหมด

```
roundN_ชื่อรอบ/
├── report/   รายงาน ทั้ง .md ที่แก้ได้ และ .pdf ที่ส่งได้
├── data/     ตารางผลดิบที่รายงานอ้างอิง
└── code/     สคริปต์ที่สร้างตารางนั้น (เฉพาะรอบที่มีสคริปต์เฉพาะกิจ)
```

**ทุกตัวเลขในโฟลเดอร์นี้มาจากไฟล์ผลลัพธ์จริง** แต่ละรอบเก็บทั้งรายงาน ข้อมูลดิบที่ใช้สร้าง
ตาราง และสคริปต์ที่รัน จึงตรวจย้อนกลับได้ทุกตัวเลข

**ผลลัพธ์** mapping 77 shared features ระหว่างสอง dataset โดยจับคู่จากลำดับคอลัมน์ ไม่ใช่จาก

**วิธี** สี่เงื่อนไข เปลี่ยนทีละอย่าง บนตัวอย่าง 300k ของ 2018 split เดิม seed เดิม

## รอบ 3 — Cross-dataset ครั้งแรก ด้วยโมเดลที่มีอยู่เดิม

📁 `round3_transfer_handoff_models/`

**คำถาม** ทำ cross-dataset ให้รันได้ก่อน ยังไม่เน้นผลดี

**วิธี** ใช้โมเดลที่เทรนไว้แล้วจากบันเดิล `cicids2017_temporal_v1` (เทรนด้วย 9 คลาส) ทำนาย
ข้อมูล 2018 แล้วยุบผลเป็น 7 คลาส ไม่ต้องใช้ข้อมูลดิบ 2017

**ผลสำคัญ** เทียบกับการเดาว่าทุกแถวเป็น Benign (macro-F1 0.1296)

| โมเดล | macro-F1 | กู้คืนได้ |
|---|---|---|
| stacking | 0.2428 | 20.3% |
| lightgbm | 0.2298 | 16.2% |
| random_forest | 0.1348 | **0.8%** |

random_forest ได้เท่าการเดาพอดี ส่วน mlp กับ logistic regression ได้ accuracy ต่ำกว่าการเดา

ตอนนั้นสรุปว่าสิ่งเดียวที่ถ่ายทอดได้คือความรู้เรื่อง traffic ปกติ (Benign 0.87–0.93) ส่วนคลาส
โจมตีพังเกือบหมด **ข้อสรุปนี้กว้างเกินไป** รอบ 4 พบว่าในทิศ 2018 ไป 2017 ซึ่งรอบ 3 วัดไม่ได้
นั้น Bot ทำได้ 0.94 และ Brute Force ทำได้ 0.91 ส่วนในทิศที่รอบ 3 วัด ข้อสรุปเดิมยังคงถูกต้อง

**การทดลองแทรก** บังคับให้โมเดลตอบได้แค่ 7 คลาสร่วม (ตัด probability ของ Heartbleed และ
PortScan ก่อน argmax) ดีขึ้นสูงสุด 0.008 และมีสองโมเดลแย่ลง จึงประเมินตอนนั้นว่าการทำคลาสให้
เท่ากันมีผลราว 1% — **การประเมินนี้วัดได้เพียงองค์ประกอบเดียว** และยังไม่มีรอบใดวัดผลรวมของ
การทำคลาสให้เท่ากันแบบแยกตัวแปรได้ ดูหัวข้อเทียบรอบ 3 กับรอบ 4

## รอบ 5 — ตรวจสอบความน่าเชื่อถือของผล ⭐ รอบล่าสุด

📁 `round5_reliability_audit/` · รายงาน `report/advisor_checklist_20260928.md` (และ .pdf)

**คำถาม** ผลของรอบ 4 เชื่อได้แค่ไหน ตอบรายการตรวจสี่ข้อของอาจารย์

**สิ่งที่เปลี่ยนก่อนตรวจ** สร้างคลัง 2018 ใหม่จากไฟล์ดิบ 10 ไฟล์ แล้ว clean ก่อน sample เหมือน
ฝั่ง 2017 ทั้งสองฝั่งได้ครบ 300,000 แถวพอดี ผลดิบอยู่ที่ `results/crossdataset/protocol_v2/`

| ข้อ | คำถาม | คำตอบ |
|---|---|---|
| 1 | AUC 1.0 ของ adversarial validation เป็น artifact ไหม | **ไม่ใช่** label-shuffle ได้ 0.49–0.51 ไม่มีแถวซ้ำคร่อม split ใน 30 การสุ่ม LR ก็แยกได้ 0.9478 ขึ้นไป |
| 2 | คนละ file/time ภายใน dataset แยกได้ง่ายไหม | **แยกได้ แต่ไม่ง่ายเท่าข้าม dataset** 0.66–0.94 เทียบ 0.95–1.00 ทุกโมเดล และโปรแกรมโจมตีตัวเดียวกันข้าม dataset ยังได้ 0.9999–1.0000 |
| 3 | feature ใดเป็น fingerprint อย่างเดียว | **แทบไม่มี** มีตัวเดียวคือ `act_data_pkt_fwd` คอลัมน์ที่บอก dataset กับคอลัมน์ที่จำแนก attack เป็นชุดเดียวกัน (rank correlation +0.72 ถึง +0.77) |
| 4 | asymmetry และผลของ split mode ยังอยู่ไหม | **ยังอยู่ทั้งคู่** asymmetry 7 จาก 7 โมเดล เล็กลงจาก 40.4 เป็น 33.6 จุด การแบ่งแบบสุ่มยังซ่อนมันไว้ ผลดีที่สุดเดิม stacking 73.9% เหลือ 40.2% |

### คะแนนจริงควบคู่ Recovery % (3 ตุลาคม 2569)

📄 `round5_reliability_audit/report/macro_f1_with_recovery_20261003.md` (และ .pdf) · ตารางต้นทาง
`results/crossdataset/protocol_v2/summary_macro_f1.csv` (ไม่ได้รันการทดลองใหม่)

macro-F1 เฉลี่ย ± SD ของ 5 seeds โหมด chronological protocol_v2 (baseline เดาว่าทุกแถวเป็น Benign
= 0.1337 บน 2018 และ 0.1294 บน 2017) ในวงเล็บคือ Recovery % ตัวเลขเดิม

| โมเดล | 2017 ไป 2018: macro-F1 ± SD (Recovery) | 2018 ไป 2017: macro-F1 ± SD (Recovery) |
|---|---|---|
| lightgbm | 0.2058 ± 0.0641 (9.9%) | **0.4480 ± 0.0079** (52.8%) |
| stacking | 0.1715 ± 0.0007 (5.4%) | **0.3674 ± 0.0386** (40.2%) |
| xgboost | 0.1712 ± 0.0001 (5.2%) | **0.3615 ± 0.0182** (39.5%) |
| logistic_regression | 0.1508 ± 0.0000 (2.8%) | **0.3493 ± 0.0000** (79.8%) |
| mlp | 0.1755 ± 0.0014 (6.1%) | **0.3107 ± 0.0248** (39.7%) |
| catboost | 0.1726 ± 0.0009 (5.4%) | **0.2226 ± 0.0041** (15.9%) |
| random_forest | 0.1717 ± 0.0001 (5.4%) | **0.1680 ± 0.0007** (7.2%) |

- **อันดับตาม Recovery กับตามคะแนนจริงไม่ตรงกัน** logistic_regression ทิศ 2018 ไป 2017 ได้ Recovery สูงสุด (79.8%) แต่ macro-F1 จริงเป็นอันดับ 4 เพราะ ceiling ของมันบน 2017 ต่ำ (0.4050) lightgbm ได้คะแนนจริงสูงสุดและชนะทุก seed
- **lightgbm ทิศ 2017 ไป 2018 ถูกดึงขึ้นโดย seed เดียว** seed 42 ได้ 0.3204 อีก 4 seeds ได้ 0.1766 ถึง 0.1776
- **SD ในโหมด chronological คือความสุ่มของโมเดลอย่างเดียว** การแบ่งและตัวอย่าง 300,000 แถวไม่เปลี่ยนตาม seed โมเดลที่ไม่มีส่วนสุ่ม (logistic_regression) จึงได้ SD = 0.0000 พอดี
- **ceiling ของ 2017 แบบ chronological ถูกกดโดย Brute Force** (F1 ≈ 0 ในทุกโมเดล เพราะ train ไม่มี SSH-Patator) ทำให้ Recovery ของทิศ 2018 ไป 2017 สูงขึ้น ดู `../ids2017/report/chronological_split_explained.md`

## เทียบรอบ 3 กับรอบ 4 ให้ถูกต้อง

รอบ 3 วัดได้ทิศเดียวคือ 2017 ไป 2018 ส่วนรอบ 4 วัดได้ทั้งสองทิศ **การเทียบต้องดูทิศเดียวกัน
เท่านั้น**

### ทิศ 2017 ไป 2018 ซึ่งเป็นทิศเดียวที่ทั้งสองรอบวัด — รอบ 4 ได้ต่ำกว่า

| โมเดล | รอบ 3 Brute Force | รอบ 4 Brute Force |
|---|---|---|
| stacking | 0.7359 | 0.0000 |
| xgboost | 0.3902 | 0.0000 |
| lightgbm | 0.2654 | 0.0000 |
| logistic_regression | 0.2394 | 0.0924 |

**แต่สรุปไม่ได้ว่ารอบ 4 แย่กว่า** เพราะเงื่อนไขต่างกันหลายอย่างพร้อมกัน

- รอบ 3 โมเดลเทรนด้วย 2017 ทั้ง corpus 1,748,579 แถว ส่วนรอบ 4 เทรนด้วย 180,000 แถว
- รอบ 3 ไม่ได้ clean ฝั่ง 2018 ส่วนรอบ 4 ตัดแถวซ้ำออก ทำให้ Brute Force ของ 2018 เหลือ 1,798 จาก 7,039 แถว
- วิธีแบ่งข้อมูลต่างกัน

### ตัวเลข 0.88 ถึง 0.91 เป็นของทิศ 2018 ไป 2017 ซึ่งรอบ 3 วัดไม่ได้

| โมเดล | Brute Force ทิศ 2018 ไป 2017 |
|---|---|
| mlp | 0.9145 |
| xgboost | 0.9017 |
| lightgbm | 0.8888 |
| stacking | 0.8831 |

**นี่คือของใหม่จริงของรอบ 4** ไม่ใช่การปรับปรุงตัวเลขเดิม

### เรื่องผลของการทำให้ชุดคลาสเท่ากัน — ยังไม่มีการวัดที่สะอาด

รอบ 3 ประเมินไว้ราว 1% จากการบังคับให้โมเดลตอบได้แค่ 7 คลาส ซึ่งวัดได้เพียงองค์ประกอบเดียว
คือคำทำนายที่เสียไปกับคลาสที่ไม่มีในเป้าหมาย

รอบ 4 เปลี่ยนหลายอย่างพร้อมกัน จึงแยกไม่ได้ว่าส่วนไหนมาจากการทำคลาสให้เท่ากัน **ทั้งสองรอบ
จึงยังไม่ได้ตอบคำถามนี้** ถ้าต้องการคำตอบต้องรันเงื่อนไขที่คุมทุกอย่างให้เหมือนกันแล้วเปลี่ยน
เฉพาะชุดคลาส

## ข้อจำกัดที่ยังเหลือ

1. **[แก้แล้วในรอบ 5]** ฝั่ง 2018 หลัง clean เคยเหลือ 262,701 แถว ไม่ครบ 300,000 ตาม protocol ตอนนี้สร้างคลังใหม่จากไฟล์ดิบ ได้ครบ 300,000 แถว
2. ช่อง calibration 10% กันไว้แล้วแต่ยังไม่ได้ใช้
3. ยังไม่ได้ทูน hyperparameter
4. **[ทำแล้วในรอบ 5]** adversarial validation พร้อม control สามชั้น
5. ตัวบอกลำดับเวลาต่างกัน 2017 ใช้ลำดับแถวในไฟล์ 2018 ใช้ timestamp จริง ลำดับแถวของ 2017 ตรงกับตารางเวลาการโจมตีระดับ ก้อนการโจมตี แต่ไม่ใช่นาฬิกา และมีแถวที่ขัดกับตารางเวลา ดู `../ids2017/report/chronological_split_explained.md`
6. **ceiling ของ 2017 แบบ chronological ถูกกดโดย Brute Force** train ของการแบ่ง 60/10/30 ไม่มี SSH-Patator เลย (อยู่ในช่อง calibration ที่ไม่ได้ใช้) และ test เป็น SSH-Patator ล้วน Brute Force จึงได้ F1 ≈ 0 ในทุกโมเดล ส่วนต่างเพดานแบบสุ่มกับ chronological ของ 2017 ราว 70% ถึง 99% มาจาก Brute Force กับ Bot ผลนี้กระทบการอ่าน Recovery % ของทิศ 2018 ไป 2017 และข้อความ "transfer จริงไม่ได้เปลี่ยน" ในรายงานรอบ 5 หัวข้อ 4.3 (คะแนนข้ามชุดเปลี่ยนด้วย) ยังไม่ได้ปรับ protocol
