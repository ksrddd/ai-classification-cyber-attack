# Cross-Dataset protocol_v3: ผลรายคลาส

เอกสารนี้แยกดู performance รายคลาสของ `protocol_v3` (train 70% / test 30%) เทียบกับ `protocol_v2` (train 60%) ว่าคะแนนเปลี่ยนเพราะคลาสไหน ไม่ดูแค่ macro-F1 รวม ทุกตัวเลขเฉลี่ยจาก 5 seeds ผลของ 7 โมเดล (lightgbm, xgboost, stacking, logistic regression, mlp, catboost, random forest) และไม่ได้ปรับ hyper-parameter ใช้ค่าเริ่มต้นของไลบรารี

macro-F1 คือค่าเฉลี่ยของ F1 ทั้ง 7 คลาสแบบน้ำหนักเท่ากัน (ตรวจกับทุกแถวของผลแล้ว ต่างกันไม่เกิน 0.0001 ซึ่งมาจากการปัดเศษ 4 ตำแหน่งของไฟล์ผล) ดังนั้นการเปลี่ยนของ macro-F1 แยกเป็นผลรวมของการเปลี่ยนรายคลาสได้เป๊ะ คลาสละ (F1 ที่เปลี่ยน / 7) เอกสารนี้จึงตอบได้ว่าคะแนนรวมเปลี่ยนเพราะคลาสอะไร ตัวเลขทุกตัวเฉลี่ยจาก 5 seeds ค่า SD รายคลาสอยู่ในไฟล์ `data/per_class_v3.csv`

ขนาดของแต่ละคลาสใน test (โหมด chronological) ต้องดูประกอบ เพราะคลาสเล็กทำให้ F1 แกว่งง่าย

### 1.4 อ่านทีละคลาส

**Brute Force** เป็นคลาสที่ทำให้ผลเปลี่ยนมากที่สุด ใน v2 train ของ 2017 ไม่มี SSH-Patator ceiling 2017 จึงต่ำและ transfer ไป 2018 เป็นศูนย์ ใน v3 ceiling กลับเป็น 0.97 ถึง 1.00 ทุกโมเดล ทิศ 2017 ไป 2018 มี 3 โมเดลที่ได้ F1 ตั้งแต่ 0.5 (lightgbm, xgboost, stacking) ที่เหลือยังเป็นศูนย์ ทิศ 2018 ไป 2017 มี 5 โมเดลที่ได้ตั้งแต่ 0.5 (lightgbm, xgboost, stacking, logistic regression, mlp) ส่วน catboost, random forest ได้ไม่ถึง 0.1 คือคลาสนี้ข้าม dataset ได้เมื่อโมเดลเป็นแบบ boosting เร็ว ๆ แต่ไม่ใช่ทุกโมเดล

**DoS** ได้ F1 ระดับต่ำถึงปานกลางในทั้งสองทิศ (2017 ไป 2018 อยู่ที่ 0.12 ถึง 0.28 และ 2018 ไป 2017 อยู่ที่ 0.19 ถึง 0.59) เทียบกับ ceiling 0.79 ถึง 0.98 ผลนี้แทบไม่เปลี่ยนระหว่าง v2 กับ v3 (ส่วนของ macro ไม่เกิน 0.005 ทั้งบวกและลบ ยกเว้นการหักล้างกับ DDoS ใน stacking ข้างต้น) DoS จึงเป็นคลาสโจมตีที่ transfer ได้ "บางส่วน" อย่างคงที่ ไม่ขึ้นกับสัดส่วน split

**DDoS** ceiling เกือบสมบูรณ์ (0.97 ถึง 1.00) แต่ transfer ทิศ 2017 ไป 2018 ได้ศูนย์เกือบทุกโมเดล (สูงสุด 0.011) และทิศ 2018 ไป 2017 มีแค่ logistic regression ที่ได้ 0.52 นอกนั้น 0.13 หรือต่ำกว่า DDoS จึงเป็นคลาสที่เสียมากที่สุดเมื่อเทียบ ceiling กับ transfer และเป็นหนึ่งในเหตุผลที่ transfer macro-F1 ต่ำ ไม่ได้ถูกกระทบจากการเปลี่ยน split

**Bot** ใน 2017 ยากแม้อยู่ใน dataset เดียวกัน ceiling 2017 อยู่ที่ 0.00 ถึง 0.27 (test 584 แถว) ขณะที่ ceiling 2018 อยู่ที่ 0.99 ถึง 1.00 ทิศ 2017 ไป 2018 มี 3 โมเดลที่ได้ F1 เกิน 0.05 (lightgbm, stacking, xgboost) และทิศ 2018 ไป 2017 มีโมเดลเดียวที่ได้เกิน 0.05 คือ lightgbm (0.87) ผลรายโมเดลของคลาสนี้จึงต่างกันมาก

**Web Attack** transfer เป็นศูนย์ในแทบทุกโมเดลและทั้งสองทิศ (สูงสุด 0.002 และ 0.018) ทั้งที่ ceiling สูง (0.83 ถึง 0.97 ไม่รวม logistic regression) และไม่เปลี่ยนระหว่าง v2 กับ v3

**Benign** ได้ F1 0.92 ถึง 0.94 (ทิศ 2017 ไป 2018) และ 0.88 ถึง 0.95 (ทิศ 2018 ไป 2017) ส่วนนี้อย่างเดียวให้ macro-F1 ราว 0.134 (57% ของคะแนนเฉลี่ย 0.236) ในทิศ 2017 ไป 2018 และ 0.131 (42% ของ 0.312) ในทิศ 2018 ไป 2017 คะแนน transfer ที่สูงกว่า baseline จึงมาจากคลาสโจมตีไม่กี่คลาส (Brute Force, DoS และ Bot ในบางโมเดล) ไม่ใช่จากการจำแนกได้ทั่วไป

### 1.5 ข้อจำกัดของการอ่านรายคลาส

- ผลรายคลาสขึ้นกับโมเดลมาก (Brute Force และ Bot ข้ามได้ใน 1 ถึง 5 จาก 7 โมเดลเท่านั้น) ค่าเฉลี่ยข้ามโมเดลจึงต้องอ่านคู่กับตารางรายโมเดล
- การแยกการเปลี่ยนของ macro-F1 เป็นรายคลาสบอกว่า "คลาสไหนเปลี่ยน" แต่ไม่ได้พิสูจน์สาเหตุ คำอธิบายเรื่อง SSH-Patator ของ Brute Force มีหลักฐานจากจำนวนแถวต่อ sub-type ส่วนการเปลี่ยนของ Bot และของ DDoS กับ DoS ใน stacking ยังไม่ได้ตรวจกลไก
- Infiltration (test 11 แถวใน 2017) วัดผลไม่ได้อย่างน่าเชื่อถือ ส่วนที่มันมีใน ceiling 2017 (+0.014) ไม่ควรตีความ
- คลาสเล็กแกว่งมากระหว่าง seed (SD รายคลาสอยู่ในไฟล์ข้อมูล) และโหมด chronological ไม่มีความแกว่งจากการแบ่ง จึงวัดได้เฉพาะความสุ่มของโมเดล
