# เปรียบเทียบผลเก่ากับผลใหม่ หลังย้ายไปใช้ Shared Schema

รันเมื่อวันที่ 9 สิงหาคม 2569 บนตัวอย่าง 300,000 แถวของ CSE-CIC-IDS2018

เอกสารนี้ตอบคำถามว่า การเปลี่ยนไปใช้ schema ร่วมสำหรับงาน cross-dataset ทำให้ผลลัพธ์
เปลี่ยนไปเท่าไหร่ และความเปลี่ยนแปลงนั้นมาจากอะไร

## 1. ข้อสรุปสำคัญที่สุด

การยุบคลาสจาก 15 เหลือ 7 ทำให้ตัวเลขพาดหัวดีขึ้นชัดเจน แต่ **ประสิทธิภาพจริงบนคลาสที่
วัดผลได้กลับแย่ลง** ตัวเลขสองชุดนี้ชี้คนละทิศกัน

| ตัววัด | ก่อนยุบคลาส | หลังยุบคลาส | ส่วนต่าง |
|---|---|---|---|
| macro-F1 ทุกคลาส | 0.7126 | 0.7880 | เพิ่ม 0.0754 |
| macro-F1 เฉพาะคลาสที่วัดได้ | 0.8575 | 0.8193 | ลดลง 0.0382 |

ตัวเลขข้างบนเป็นของ lightgbm ทิศทางเดียวกันนี้เกิดกับทุกโมเดล สาเหตุคือการยุบคลาสเอาคลาส
ที่โมเดลทำได้ดีไปรวมกับคลาสที่พัง ทำให้คลาสดีถูกดึงลง ขณะเดียวกันก็ทำให้คลาสจิ๋วที่เคยได้
ศูนย์หายไปจากการนับ macro ผลลบสองอย่างหักกลบกันจนดูเหมือนดีขึ้น

ถ้ารายงานเฉพาะตัวเลขพาดหัว จะสรุปผิดทันทีว่าการยุบคลาสทำให้โมเดลดีขึ้น

## 2. วิธีทดลอง

รันสี่เงื่อนไข เปลี่ยนทีละอย่าง

| เงื่อนไข | feature | คลาส |
|---|---|---|
| A ฐานเดิม | 77 มี Protocol ไม่มี Dst Port | 15 |
| B shared schema | 76 ไม่มีทั้งสอง | 15 |
| B+ shared เพิ่ม Dst Port | 77 ไม่มี Protocol มี Dst Port | 15 |
| C shared เพิ่มยุบคลาส | 76 | 7 |

เงื่อนไขที่คุมให้เหมือนกันทุกเงื่อนไข

- ใช้ตัวอย่างชุดเดียวกัน 300,000 แถว
- คำนวณ temporal split ครั้งเดียวจาก label 15 คลาส แล้วใช้ร่วมกันทุกเงื่อนไข ดังนั้นแถว train 209,989 แถวและ test 90,011 แถวเป็นแถวเดียวกันเป๊ะทุกเงื่อนไข
- ใช้ hyperparameter เดิมจาก `tuning.json` ของ bundle `300k_temporal_tuned_fair` ไม่มีการทูนใหม่
- ใช้สี่โมเดลที่รันเร็ว คือ lightgbm, xgboost, random forest และ logistic regression

ผลที่เห็นจึงมาจากการเปลี่ยน schema อย่างเดียว ไม่ใช่จากการแบ่งข้อมูลหรือการทูน

## 6. ส่วนต่างทีละขั้น

### 6.1 ขั้น A ไปหา B คือการตัด Protocol ออก

| โมเดล | ส่วนต่าง macro ทุกคลาส | ส่วนต่าง macro คลาสที่วัดได้ |
|---|---|---|
| lightgbm | เพิ่ม 0.0016 | เพิ่ม 0.0021 |
| xgboost | เท่าเดิม | เท่าเดิม |
| random forest | ลด 0.0006 | ลด 0.0007 |
| logistic regression | เพิ่ม 0.0131 | เพิ่ม 0.0164 |

**ตัด Protocol ทิ้งไม่มีราคาต้องจ่าย** ทั้งสี่โมเดลขยับไม่เกิน 0.017 และสามในสี่ขยับไม่ถึง
0.002 แปลว่าการทำให้ schema เข้ากันได้กับ 2017 ไม่ได้ทำให้เสียอะไรเลย

### 6.2 ขั้น B ไปหา B+ คือการเพิ่ม Dst Port กลับเข้ามา

| โมเดล | ส่วนต่าง macro ทุกคลาส | ส่วนต่าง macro คลาสที่วัดได้ |
|---|---|---|
| lightgbm | เพิ่ม 0.0038 | เพิ่ม 0.0047 |
| xgboost | ลด 0.0130 | เพิ่ม 0.0171 |
| random forest | เพิ่ม 0.0121 | เพิ่ม 0.0151 |
| logistic regression | ลด 0.0084 | ลด 0.0105 |

กรณี xgboost น่าสนใจที่สุด ตัวเลขพาดหัวบอกว่าแย่ลง 0.0130 แต่คะแนนบนคลาสที่วัดได้ดีขึ้น
0.0171 สาเหตุคือคลาส `Brute Force -Web` ที่มี test flow แค่ 4 แถวตกจาก 0.40 เป็น 0.00
คลาสเดียวถือน้ำหนักหนึ่งในสิบห้า จึงกลบผลบวกของคลาสที่เหลือทั้งหมด

ที่ Dst Port ช่วยจริงคือคลาสที่ยากที่สุด

| Infilteration lightgbm | 0.1185 | 0.1703 |
| Infilteration random forest | 0.1262 | 0.1782 |
| Bot lightgbm | 0.9925 | 0.9994 |
| DoS Slowloris random forest | 0.7647 | 0.8850 |

## 8. ข้อค้นพบที่สำคัญ

### 8.1 การยุบคลาสไม่ได้แก้คลาสที่พังจริง

`Infilteration` เป็นคลาสเดียวที่ปรากฏเหมือนกันทั้งก่อนและหลังยุบ เพราะจับคู่หนึ่งต่อหนึ่ง
ค่า F1 ของมันแทบไม่ขยับเลย

| เงื่อนไข | Infiltration F1 lightgbm |
|---|---|
| B ก่อนยุบคลาส | 0.1185 |
| C หลังยุบคลาส | 0.1173 |

คลาสที่พังยังพังเท่าเดิม สิ่งที่การยุบคลาสทำคือย้ายคลาสจิ๋วที่ทำคะแนนไม่ได้ไปซ่อนไว้ในคลาส
ใหญ่ ไม่ใช่การทำให้โมเดลเรียนรู้ได้ดีขึ้น

### 8.2 การยุบคลาสทำให้คลาสที่ดีอยู่แล้วแย่ลง

| คลาสต้นทาง | F1 ก่อนยุบ | คลาสปลายทาง | F1 หลังยุบ |
|---|---|---|---|
| SSH-Bruteforce | 1.0000 | Brute Force | 0.8860 |
| FTP-BruteForce | 0.7946 | Brute Force | 0.8860 |
| DoS attacks-Hulk | 1.0000 | DoS | 0.9269 |
| DoS SlowHTTPTest | 0.6281 | DoS | 0.9269 |

การรวมคลาสที่ทำได้สมบูรณ์เข้ากับคลาสที่ทำไม่ได้ ทำให้ผลลัพธ์ไปกองอยู่ตรงกลาง ข้อมูลว่า
โมเดลแยก SSH-Bruteforce ได้สมบูรณ์แบบหายไปจากรายงาน

### 8.3 ปัญหาคลาสจิ๋วไม่ได้หายไปหลังยุบเหลือ 7 คลาส

คลาส `Web Attack` หลังยุบรวมสามคลาสเข้าด้วยกันแล้ว ยังมี test flow เพียง 7 แถว ยังไม่ถึง
เกณฑ์ที่วัดผลได้ ปัญหาลดจากสี่คลาสจิ๋วเหลือหนึ่งคลาสจิ๋ว แต่ไม่ได้หมดไป

ข้อนี้แก้ความเข้าใจเดิมที่เคยประเมินว่าการยุบเหลือ 7 คลาสจะทำให้ปัญหาคลาสจิ๋วหมดไป

### 8.4 logistic regression ตอบสนองกลับทิศกับโมเดลต้นไม้

การยุบคลาสทำให้ logistic regression แย่ลงทั้งสองตัววัด ต่างจากอีกสามโมเดลที่ตัวเลขพาดหัว
ดีขึ้น สาเหตุคือ DDoS ตกจาก 0.97 เหลือ 0.895 และ DoS ตกเหลือ 0.913 เพราะโมเดลเชิงเส้นเคย
แยกคลาสย่อยเหล่านั้นออกจากกันได้ พอถูกบังคับให้รวมเป็นก้อนเดียว ขอบเขตการตัดสินใจที่เคย
ใช้ได้ก็ใช้ไม่ได้อีก

## 9. ผลต่อแผนงาน cross-dataset

1. **การย้ายไป shared schema ปลอดภัย** การตัด Protocol ออกไม่มีราคาต้องจ่าย เดินหน้าใช้ 77 features ร่วมได้เลย
2. **ต้องตัดสินใจเรื่อง Dst Port ก่อนรัน cross-dataset** ตอนนี้ pipeline 2017 เก็บไว้ แต่ pipeline 2018 ตัดทิ้ง ทั้งสองฝั่งต้องทำเหมือนกัน ผลข้างบนบอกว่ามันช่วยคลาสที่ยากจริง โดยเฉพาะ Infiltration ที่ขึ้นจาก 0.12 เป็น 0.17 แต่มันก็เป็น feature ที่ผูกกับ lab มากที่สุดตัวหนึ่ง จึงเป็นตัวต้องสงสัยอันดับต้นในการทำ adversarial validation
3. **ต้องรายงาน macro-F1 สองแบบเสมอ** ผลชุดนี้แสดงให้เห็นว่าการรายงานแบบเดียวนำไปสู่ข้อสรุปที่กลับทิศกับความจริง
4. **ต้องระวังการอ่านผลของอาจารย์** ถ้าอาจารย์รายงานผล 7 คลาสด้วยตัวเลขพาดหัวอย่างเดียว ตัวเลขนั้นจะสูงกว่าความเป็นจริง และเมื่อนำไปเทียบกับผล cross-dataset จะทำให้ช่องว่างดูใหญ่เกินจริง

## 10. สิ่งที่ยังทำไม่ได้

ยังไม่ได้รันเงื่อนไข D คือการข้ามชุดข้อมูลจริง เพราะไม่มีข้อมูลดิบของ CICIDS2017 อยู่ในเครื่อง

ผลชุดนี้ทั้งหมดเป็นฝั่ง 2018 อย่างเดียว จึงยังตอบไม่ได้ว่าการข้ามชุดข้อมูลมีราคาเท่าไหร่
ตอบได้แค่ว่าการเตรียม schema ให้พร้อมสำหรับการข้ามชุดข้อมูลมีราคาเท่าไหร่ ซึ่งคำตอบคือ
แทบไม่มีราคาเลยในส่วนของ feature แต่มีราคาแฝงที่มองไม่เห็นในส่วนของการยุบคลาส
